## 四、出厂等价实例冒烟（notification4j-app-1.4.0.jar）

- 启动形态：`framework4j.datasource.enabled=true`（无 spring.datasource.*、无手工 exclude）+ PG16/Redis7（25432/26379）+ 引擎提速参数。
- **单池三零**：启动日志原生 Druid wrapper 计 0 / Hikari 计 0 / ERROR 计 0；健康探针 `GET /nfy/api/v1/ops/health` → `{"status":"UP","checks":{"db":{"status":"UP"},"redis":{"status":"UP"}}}`。
- **PPM 路由闸**：未认证 `GET /nfy/platform/api/v1/messages`（及 `/{id}`）→ `{"code":10200,"message":"未提供认证令牌"}`。
- **已认证全链**（PLATFORM client 换 token 后）：
  - `GET /messages?limit=1&user_id=u_plat` → `code=0, total=0`（user_id 子查询筛选语义生效：该库无此用户消息）
  - `GET /messages?limit=1` → `code=0, total=605`（跨租户全量可见，多租户数据混排）
  - `GET /messages/{id}` → `code=0`，13 字段契约形 `message_id/tenant_id/type_code/level/title/status/receiver_count/created_at/biz_no/content/link_url/sender/read_count`（Long→字符串口径），`read_count=0`

## 六、发版链路异常登记（过程记录，均已处置）

| 事项 | 处置 |
|---|---|
| 升版后 m2 依赖链断裂（IT 首跑找不到 1.4.0 parent/client-starter） | 补 `mvn -o install -N`（parent pom）+ `mvn -o install -pl notification4j-client-starter`（10/10）后恢复——升版必然连锁，非缺陷 |
| 非 clean install 残留旧 `notification4j-app-1.3.0.jar`，启动脚本 glob `head -1` 字典序选中旧包（首启实为旧 jar） | 杀实例、清理旧 jar、重启 1.4.0 并重做全部验证；脚本 glob 加固为 `sort -V \| tail -1`（版本序取最高），防复发 |
| `/actuator/health` 返回 10400（app 未引入 actuator） | 健康探针口径为白名单内 `/nfy/api/v1/ops/health`（UP + db/redis 分项），报告按此口径 |
| IT 运行日志偶发 `TaskUtils$LoggingErrorHandler` 调度异常日志 | 测试场景注入的预期调度异常，136 用例全过，非失败项 |
