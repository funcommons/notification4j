# ADR-0011 免打扰时段：计划期 next_retry_at 推迟（引擎零改动）

日期：2026-09-17 ｜ 状态：Accepted ｜ 关联：V1.2 编码第 20 步、ADR-0003（外发引擎 DB 队列）

## 背景

订阅免打扰（`nfya_subscription.quiet_hours` jsonb，V1.2 落地）语义参照 Courier quiet hours：**推迟发送非丢弃**——静默窗结束消息须自动补发。候选落点：①发送侧（引擎扫描时判定）；②计划侧（投递计划展开时判定）；③丢弃/跳过（SKIPPED 终态）。

## 决策

**计划期推迟**：`DeliveryPlanService` 展开订阅矩阵时判定静默窗（跨午夜两段：`t≥start || t<end`），命中 → 该订阅生成的投递行 `next_retry_at` 直接置为窗结束时刻（窗前段→当日 end、窗后段→次日 end，系统默认时区）。`DeliveryEngine` 零改动——其本就按 `next_retry_at <= now` 扫描，延迟语义免费获得。

豁免口径：URGENT 走全量 ENABLED 渠道路径不经订阅矩阵（天然豁免，产品 §237 定死）；INAPP 落库即达不产投递行（天然豁免）。

## 理由

- 引擎侧判定需在扫描 SQL 中 join 订阅表并做时窗计算（每轮全量成本），或 claim 后二次延迟（占 SENDING 槽位触发 reaper）——均复杂化热点路径；
- 计划期判定一次性、无热点、与既有订阅矩阵展开同事务同数据源；
- `next_retry_at` 复用引擎既有重试调度字段，无 schema 变更（列已在，V1.0 零迁移承诺维持）。

## 影响

- 静默窗在**发送时刻**判定而非用户阅读时刻：窗内入队、窗结束自动发出，投递不丢失不取消；
- 时区边界：按服务端系统默认时区，单时区部署（多时区用户时区概念设计未定义，登记边界）；
- 脏数据（jsonb 解析失败）fail-open 即时投递并告警——宁可打扰不丢消息；
- IT：NfyQuietHoursTest 8 用例（窗口构造法零 sleep；含公告订阅者外发路径，第 22 步补）。
