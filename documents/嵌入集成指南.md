# notification4j 消息中心嵌入集成指南（V1.0）

> 面向接入方前端/后端工程师。目标：30 分钟内把消息中心（铃铛 + 完整五页）嵌入你的应用。

## 一、总览

```
接入方页面                                notification4j
┌────────────────────────┐                ┌─────────────────────┐
│ <iframe src=.../bell>  │──NFY_READY────▶│  消息中心 (iframe)   │
│                        │                │                     │
│ 租户后端代换短期 token  │◀─NFY_TOKEN────│  握手完成后自持 token │
│ (open_id+secret→JWT)   │                │                     │
└────────────────────────┘                └─────────────────────┘
```

- **铃铛单页**：`GET {nfy-host}/nfy/tenant/page/bell`（48×48 起，角标+最近 5 条）
- **完整五页**：`{nfy-host}/nfy/tenant/app/messages`（消息/公告/渠道/订阅/投递，侧栏壳）

## 二、postMessage 握手协议（推荐级，token 不进 URL/存储）

| 方向 | 消息 | 说明 |
|---|---|---|
| iframe → 父页 | `{type:'NFY_READY'}` | **周期重发（500ms）** 直至收到 NFY_TOKEN——防父页监听未就绪死锁 |
| 父页 → iframe | `{type:'NFY_TOKEN', token:'<JWT>', user_id:'u_1'}` | **origin 必须在白名单**，否则静默忽略；token/user_id 只进内存 |
| iframe → 父页 | `{type:'NFY_URGENT', total:N}` | URGENT 未读首次出现时通知（30s 轮询口径） |
| iframe → 父页 | `{type:'NFY_NAVIGATE', url:'...'}` | 「查看全部」跳转请求（父页自行打开完整消息中心） |

### 父页最小实现（~30 行）

```html
<iframe id="nfy" src="https://nfy.example.com/nfy/tenant/page/bell"></iframe>
<script>
  window.addEventListener('message', async (e) => {
    if (e.data?.type !== 'NFY_READY') return;
    // 1. 向你的租户后端要一个短期 token（≤1h，见下节）
    const { token } = await fetch('/my-backend/nfy-token?user=u_1').then(r => r.json());
    // 2. 下发给 iframe（origin 白名单由 nfy 侧配置）
    document.getElementById('nfy').contentWindow
      .postMessage({ type: 'NFY_TOKEN', token, user_id: 'u_1' }, '*');
  });
</script>
```

## 三、token 代换（租户后端）

```http
POST https://nfy.example.com/nfy/api/v1/auth/token
Content-Type: application/x-www-form-urlencoded

grant_type=client_credentials&client_id={租户OpenID}&client_secret={租户密钥}
```

- 返回 `access_token`（TENANT 型 JWT，默认 8h）——代换给 iframe 时建议**按用户签发短会话**或直接下发租户级 token（V1.0 口径：X-User-Id 透传不鉴权；推荐级加固=服务端校验 X-User-Id 与 token claim 绑定，接入方按需启用）
- token 过期：iframe 内展示「会话已过期，请刷新」占位并**重新发起 NFY_READY 握手**，不打断父页

## 四、origin 白名单（服务端/前端配置）

前端构建注入环境变量：

```
VITE_NFY_PARENT_ORIGINS=https://app.example.com,https://admin.example.com
VITE_NFY_BASE_URL=/nfy/api/v1
```

或页面 props：`<BellPage origins="https://app.example.com" />`。
白名单外的 `NFY_TOKEN` 消息一律忽略（防恶意父页注入）。

## 五、完整消息中心路由

| 路由 | 用途 |
|---|---|
| `/nfy/tenant/app/messages` | 消息列表（未读筛选/标已读/加载更多） |
| `/nfy/tenant/app/announcements` | 公告（需确认的「我知道了」） |
| `/nfy/tenant/app/channels` | 我的渠道（注册/验证/启停/删除） |
| `/nfy/tenant/app/subscriptions` | 订阅矩阵（类型×渠道开关，强制类型锁定） |
| `/nfy/tenant/app/deliveries` | 投递记录（筛选/分页，DEAD 行可重投） |
| `/nfy/tenant/page/bell` | 铃铛单页（48×48 iframe） |

## 六、安全边界清单

- postMessage origin 白名单（前端 `VITE_NFY_PARENT_ORIGINS` + 后端 oem.hosts）
- token 内存持有（不写 URL/sessionStorage/localStorage）
- iframe 内所有 API 请求经租户后端可观测（token 由租户后端代换签发）
- SSRF：用户自注册 webhook 仅允许官方域名白名单（钉钉/企微/飞书）+ 443 端口 + DNS 禁内网段
- 签名：按租户开关（`privileges.signature`，SEC-001 注册/轮换密钥）
