# ADR-0007: token 型别方案 A——PLATFORM/TENANT 独立型别

## 状态
proposed（2026-09-16）

## 上下文
平台域与租户域必须硬隔离（《租户设计》§5.3 P0：禁止同型别裸奔）。benefit4j 采用方案 B（单型别 + 平台域入口校验 tenant_id==0），属既有系统最小改造的妥协。

## 备选方案
- A. 独立型别：token claim `type=PLATFORM/TENANT`，拦截器按型别硬隔离，互打 `10207`（HTTP 200 + 信封，应用层拦截；裸 401 仅网关层——对齐 mc-api-spec 铁律 1）
- B. 单型别 + 零值校验：平台域入口统一校验 claim tenant_id==0

## 决策
选 A。新系统无历史包袱，一步到位；benefit4j 的 B 方案是其踩坑后的补救形态（《租户设计》§5.3 反例即其实录），不继承。

## 后果
正面：隔离由 token 结构本身保证，任何新平台域端点无需记得加入口校验；负面：换 token 端点需按凭据类型签发型别（平台密钥 env 配置 vs 租户库表，天然可分）。
